# strongSwan (IKEv2) 客户端连接方法汇总

本文汇总所有主流客户端连接本机 strongSwan IKEv2 服务端的方法。**服务端是加密的**（IKEv2/IPsec，数据走 ESP，实测 `ESP:AES_CBC_128/HMAC_SHA2_256_128`）。

## 0. 前置信息

| 项 | 值 |
|---|---|
| 服务器地址 | `192.168.0.106` |
| 协议 | IKEv2 |
| 端口 | `500/udp`、`4500/udp` |
| 远程 ID | `192.168.0.106`（= 服务端证书 CN/SAN） |
| VPN 网段 | `10.10.10.0/24` |
| 认证方式 | 证书（客户端证书由本机 CA 签发） |

客户端文件（`clients/`）：

| 文件 | 说明 | 用在哪 |
|---|---|---|
| `ca.crt` | CA 证书 | 所有平台校验服务端 |
| `client1.crt` | 用户证书 | 分离文件方式 |
| `client1.key` | 用户私钥（**无口令**） | 分离文件方式 |
| `client1.p12` | 用户证书+私钥+CA，**空口令** | Windows/macOS/iOS/Android |
| `client1-pass.p12` | 同上，口令 **`test`** | 需要口令的平台 |
| `strongswan-client.conf` | Linux strongSwan 命令行配置 | Linux CLI |

> 客户端类型共 **3 类认证方式**：IKEv2 证书（本方案）、IKEv2 EAP、IKEv1 PSK/XAuth；本文只讲本服务端支持的**证书方式**。
> 客户端连接方式按平台分 **8 种**，下面逐一说明。

## 1. Linux — strongSwan 命令行（✅ 已实测）

适合无桌面/服务器环境。需要 `strongswan` + `strongswan-starter`。

```bash
# 1) 放证书
sudo cp ca.crt       /etc/ipsec.d/cacerts/
sudo cp client1.crt  /etc/ipsec.d/certs/
sudo cp client1.key  /etc/ipsec.d/private/

# 2) /etc/ipsec.conf
sudo tee /etc/ipsec.conf >/dev/null <<'EOF'
config setup
    uniqueids=no

conn ikev2-client
    keyexchange=ikev2
    right=192.168.0.106
    rightid=192.168.0.106
    rightsubnet=0.0.0.0/0
    left=%defaultroute
    leftcert=client1.crt
    leftid=@client1
    leftsendcert=always
    leftsourceip=%config
    auto=add
EOF

# 3) /etc/ipsec.secrets
echo ': RSA client1.key' | sudo tee /etc/ipsec.secrets >/dev/null

# 4) 连接
sudo ipsec restart
sudo ipsec up ikev2-client
ip -4 addr show | grep 10.10.10      # 拿到 10.10.10.x
sudo ipsec down ikev2-client         # 断开
```

> 关键：`leftsendcert=always` 必须加，否则客户端不发证书，服务端返回 `AUTH_FAILED`。

## 2. Linux — NetworkManager 图形界面

需安装 `network-manager-strongswan`。控制中心 → 网络 → VPN → 添加 → **IPsec/IKEv2 (strongswan)**：

| 界面字段 | 导入内容 |
|---|---|
| 网关 / 服务器 | `192.168.0.106` |
| 认证类型 | **证书/私钥**（Certificate/Private key） |
| 证书（CA） | `ca.crt` |
| 用户证书 | `client1.crt`（或 `client1.p12`） |
| 私钥 | `client1.key`（用 p12 时无需单独选） |
| 私钥密码 | 空（`client1.p12`）/ `test`（`client1-pass.p12`） |
| 远程 ID | `192.168.0.106` |
| 选项 | 勾选"请求内网 IP" |

> ⚠️ **UOS 的 AppArmor 限制**：证书/私钥放在家目录会报 `Permission denied`。必须先把 `ca.crt`、`client1.crt`、`client1.key` 放到 `/etc/ipsec.d/`，界面里选该路径下的文件。

## 3. Linux — NetworkManager nmcli（无头）

```bash
sudo nmcli connection add type vpn con-name ikev2 vpn-type strongswan \
  vpn.data "address=192.168.0.106,method=key,\
certificate=/etc/ipsec.d/ca.crt,usercert=/etc/ipsec.d/client1.crt,\
userkey=/etc/ipsec.d/client1.key,virtual=yes,encap=no,password-flags=4"
sudo nmcli connection up ikev2
```

> ⚠️ 两点：
> 1. 证书同样要放在 `/etc/ipsec.d/`（AppArmor）。
> 2. 无图形会话时，若私钥/p12 有口令，会报"没有有效的密钥"（要 secret agent 弹框）；用**无口令**的 `client1.key` 可避免。
> 3. `nmcli modify vpn.data` 会**整体替换**，改键时要把所有键一起写。

## 4. Windows — 内置 IKEv2

1. 双击 `client1.p12` 导入（空口令；若用 `client1-pass.p12` 则输 `test`），存入"**个人**"。
2. 把 `ca.crt` 导入"**受信任的根证书颁发机构**"。
3. 设置 → 网络和 Internet → VPN → 添加：
   - VPN 提供商：`Windows（内置）`
   - VPN 类型：**IKEv2**
   - 服务器名称：`192.168.0.106`
   - 身份验证：**证书** → 选择 `client1`
4. 连接。

---

## 5. macOS — 内置 IKEv2

1. 双击 `client1.p12` 加入"登录"钥匙串（输入 `test` 或空）；`ca.crt` 加入"系统"钥匙串并设为**始终信任**。
2. 系统设置 → 网络 → VPN → 添加：
   - 类型：**IKEv2**
   - 服务器地址：`192.168.0.106`
   - 远程 ID：`192.168.0.106`
   - 本地 ID：`client1`
   - 认证设置 → 认证方式：**证书** → 选 `client1`
3. 连接。

## 6. iOS / iPadOS — 内置 IKEv2

1. 把 `client1.p12`（和 `ca.crt`）通过 AirDrop/邮件发送到设备并安装；在"设置 → 通用 → VPN 与设备管理"里**信任**证书。
2. 设置 → 通用 → VPN 与设备管理 → VPN → 添加配置：
   - 类型：**IKEv2**
   - 服务器：`192.168.0.106`
   - 远程 ID：`192.168.0.106`
   - 本地 ID：`client1`
   - 用户鉴定：**证书** → 选 `client1`
3. 连接。

---

## 7. Android — strongSwan VPN Client（官方 App）

1. 安装 **strongSwan VPN Client**。
2. 导入 `client1.p12`（设置里"导入 VPN 配置文件"或让 App 读取）。
3. 新建配置：服务器 `192.168.0.106`，IKEv2，认证选证书（客户端证书 `client1`），CA 选 `ca.crt`。
4. 连接。

---

## 8. Android — 内置 IKEv2

1. 安装 `client1.p12`（设置 → 安全 → 加密与凭据 → 安装证书 → VPN 和应用用户证书）。
2. 设置 → 网络和互联网 → VPN → 添加：
   - 类型：**IKEv2/IPSec MSCHAPv2**（若用证书则选对应证书类型）
   - 服务器：`192.168.0.106`
   - IPsec 标识符：`192.168.0.106`
   - 选择用户证书 `client1`
3. 连接。

## 10. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `AUTH_FAILED` | 客户端没发证书：加 `leftsendcert=always` |
| `Permission denied`（Linux） | UOS AppArmor：证书放 `/etc/ipsec.d/` |
| "没有有效的密钥"（nmcli） | 无 secret agent：用无口令 `client1.key`，或改用图形界面 |
| 连不上 | 确认服务端在跑、`500/4500` 未被 L2TP/IPsec / VPNC 占用 |
| 换服务器 IP 后连不上 | 证书 CN/SAN 绑定了 IP，需重签证书 |

### FAQ

**Q1：图形界面（NetworkManager）连不上 / 一直 `AUTH_FAILED`？**

A：图形界面要能连，必须**同时满足三点**（缺一不可）：

1. **服务端 `rightsendcert=always`**（`setup-strongswan.sh` 已内置）。若为 `never`，服务端不会在 IKE_SA_INIT 里发 `CERTREQ`；而 NetworkManager 的 strongswan 插件用默认 `leftsendcert=ifasked`（只有对端先索取才回证书），于是客户端**不发自己的证书** → 服务端 `no trusted RSA public key found for 'CN=client1'` → `AUTH_FAILED`。
   - 现象：客户端 charon 日志的 IKE_AUTH 请求里只有 `CERTREQ`、没有 `CERT`。
2. **服务端证书 CN/SAN = 当前服务器 IP**。换 IP 后必须重签；`setup-strongswan.sh` 现在会自动检测并**只重签服务端证书**（保留 CA，客户端证书不用换）。否则客户端报 `constraint check failed: certificate does not confirm identity '<IP>'`。
3. **客户端图形界面勾选“请求内网 IP”**（对应 `virtual=yes`）。否则服务端报 `expected a virtual IP request, sending FAILED_CP_REQUIRED` + `TS_UNACCEPT`，IKE_SA 虽建立但拿不到 `10.10.10.x`。

> 命令行方式（本文 §1）需要在 `/etc/ipsec.conf` 显式写 `leftsendcert=always`；图形界面靠服务端 `rightsendcert=always` 触发 `CERTREQ` 即可，无需客户端额外设置。
> 本机 V20 的 `network-manager-strongswan 1.4.4` 不支持 `leftsendcert`，但按上面三点配置后 GUI 同样可用。

**Q2：strongSwan 和 L2TP/IPsec / VPNC 能同时开吗？**

A：不能。三者都要占用 UDP `500/4500`，只能三选一。

- 启用 strongSwan：`docker stop ipsec-vpn-server vpnc-server && docker start strongswan-server`（`setup-strongswan.sh` 会自动停 `ipsec-vpn-server`）。
- 切到 VPNC：`docker stop strongswan-server && docker start vpnc-server`（或重跑 `SERVER_IP=<IP> ./setup-vpnc.sh`）。
- 切回 L2TP/IPsec：`docker stop strongswan-server vpnc-server && docker start ipsec-vpn-server`。
- 切换后用 `docker ps` 确认哪个在跑，客户端再连对应服务。
